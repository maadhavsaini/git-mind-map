The Critical Path is the longest sequence of tasks needed to complete a project in the minimum time possible. Basically every task that is required to do in order to complete the project.
![[Pasted image 20260405092128.png]] %% Red lines are crit path %%
Critical Path tasks directly affect the length of the project (if a crit path task takes an extra day to do, the whole project is pushed back a day), while non-crit path tasks can be pushed around since they have float / slack.
Use with a Work Breakdown Structure.

## Critical Path
shows you the minimum time required (ie. the most important steps) to finish the project.
EXAMPLE: when baking a cake, you need to make the dough, pop it in the oven, and then add icing. Making fries on the side is a non-critical activity, as in that changing when you make the fries will not affect how long it takes for the cake to be made. However, if you make the dough 20 minutes later than you expected, now the whole project has been delayed by 20 minutes.

YOU can guess how long each task will take using the OMP system!!!
Optimistic : if everything goes as well as possible
Most Likely: how long you think the task will ACTUALLY take (speaking from past experiences, after careful consideration, etc)
Pessimistic Time: if nothing goes as well as possible, the longest possible time it would take

## SLACK
Tasks on the critical path have no slack. if you saw the cake story, notice how the fries can be made anytime (lots of slack) without disrupting the project, while making the dough late directly affects the duration of the project (no slack). 
Understand which tasks have slack and which don't, to prioritize.
